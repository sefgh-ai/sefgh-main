# Proposed key HTTP contract, version 1

KEYS-HTTP-001 adds HTTP adapters around the reviewed Go key core. They are
**unregistered**: neither `cmd/api` nor Next.js routes/imports them. There is no
production store, live key, migration, new switch or browser change. This does
not replace the existing [plaintext route contract](../playground-keys/README.md).
Its approved hashed-key direction is in [the plan](../../docs/plans/playground-keys.md).

`cases.json` records 36 proposed scenarios. The Go fixture runner uses the actual
HTTP adapter and lifecycle service with the existing test-only atomic store,
synthetic session verification and a local GitHub server. The native tests add
timeouts, concurrency/state, replay, privacy and failure boundaries. All policy
numbers are synthetic: four active keys, 40 name runes, three attempts per key
and four per owner per minute, one-hour lifetime, one-second completion timeout.
They are not rollout defaults or production approvals.

| Endpoint | Credential | Proposed result |
|---|---|---|
| POST /api/v1/keys | Verified Supabase bearer | 201 `{key: metadata, secret: rawKey}`; secret revealed once |
| GET /api/v1/keys | Verified Supabase bearer | 200 `{keys: metadata[]}`; never private verifier or raw key |
| DELETE /api/v1/keys/{id} | Verified Supabase bearer | 204, idempotent; missing and foreign keys indistinguishable |
| GET /api/v1/search | New API-key bearer | Existing search JSON after admission and confirmed completion; only explicitly public rows |

All responses are `no-store`. Authentication is bearer-only; cookies and query
credentials are not accepted. Management's session factory must verify the
Supabase session and return its owner plus a management capability bound to the
same user's bearer. HTTP JSON cannot supply an owner. The factory is not a
database implementation, and these tests do not establish RLS. API keys never
become Supabase users or GitHub tokens.

Creation accepts only canonical `name` and `scopes` members. Duplicates, case or
Unicode aliases, extra members, trailing JSON, invalid UTF-8 and wrong value
types fail. JSON body is bounded to 8 KiB; media type must be application/json
with absent/UTF-8 charset. Core name/scope/active limits still apply. A failed or
ambiguous creation does not reveal a secret or automatically create a second key.

Public search uses the existing Go GitHub parser and response mapper with no
GitHub Token setting. It creates a new upstream request without caller headers,
uses an owned client/transport with no cookie jar or ambient proxy callbacks, refuses redirects, and suppresses the
legacy mapper's detailed transport logger. No supplied/default client, transport, protocol wrapper or proxy hook is inherited;
only a bounded upstream timeout is configurable. Real wiring still needs review. No configurable private-read
credential is introduced. Reply items must each have one canonical `private:
false` member; private, missing, duplicate or aliased visibility is refused.

Request IDs are generated by the server with 128 random bits. Caller IDs do not
control reservation identity. Oversized query strings (over 4 KiB) fail before
admission. Admitted attempts spend the proposed attempt quota even if the
existing query validator returns 400 without contacting GitHub; this charging
choice must be reviewed before activation. Denied quota and replay perform no
provider work. Responses are buffered to 16 MiB and cannot be released as
success until completion is confirmed. Provider 400/429/500 errors retain the
existing public mapper's fixed JSON after accounting succeeds.

Accounting failure returns fixed 503, withholding provider output. A required
server-only recovery sink receives the exact safe completion with a fresh,
uncancelled one-second budget. The HTTP client never receives that receipt.
Sink failure still refuses success. The future sink must durably retain it;
pending-attempt reconciliation/retention remain production gates, especially
for process death or a broken/panicking adapter.

The whole request begins with a maximum 18-second context and socket read
deadline, before session checks/body reads. The read deadline remains through
net/http body draining. GitHub requests are bounded to ten seconds and inherit
earlier cancellation. Core completion is at most ten additional seconds and
recovery one second: the maximum combined 29 seconds stays below the server's
30-second write limit. Trusted session/storage callbacks must honor contexts.

Fixed error mapping: invalid auth 401, invalid creation 400, size 413/414,
media 415, active-key cap 409, quota 429, timeout 504, cancellation 408,
unavailable/ambiguous/accounting 503. Unknown routes return 404 and unsupported
methods 405 with Allow. No response/log exposes errors, panic values, credentials,
verifiers, arbitrary provider payloads or user search text through this adapter.

Required next evidence: authoritative schema/RLS/grants/roles, owner-reviewed
SQL and rollout policy, real storage/recovery conformance and two-user tests,
show-once UI, actual server/Next wiring, forwarding, preview and rollback. R039
stays open, and original route count stays23/25 until the domain is completed.
